Host dedicato:: L'agente non è supportato su un host condiviso con altre applicazioni. L'host deve essere un host dedicato.


VPC e sottorete:: Quando crei l'agente della Console, devi specificare la VPC e la subnet in cui deve risiedere.


VNet e sottorete:: Quando crei l'agente della Console, devi specificare la VNet e la subnet dove deve risiedere.


Connessioni alle reti target:: L'agente Console richiede una connessione di rete alla posizione in cui vuoi creare e gestire i sistemi. Ad esempio, la rete in cui vuoi creare sistemi Cloud Volumes ONTAP o un sistema storage nell'ambiente locale.


Accesso Internet outbound:: La posizione di rete in cui distribuisci l'agente della Console deve avere una connessione Internet outbound per contattare endpoint specifici.


Endpoint contattati dalla NetApp Console:: Quando usi la NetApp Console basata sul web fornita tramite il layer SaaS, questa contatta diversi endpoint per completare le attività di gestione dei dati. Questo include gli endpoint che vengono contattati per distribuire l'agente della Console dalla Console.

regione Azure:: Se usi Cloud Volumes ONTAP, l'agente della Console deve essere distribuito nella stessa regione di Azure dei sistemi Cloud Volumes ONTAP che gestisce, oppure nella  https://docs.microsoft.com/en-us/azure/availability-zones/cross-region-replication-azure#azure-cross-region-replication-pairings-for-all-geographies["coppia di regioni Azure"^] per i sistemi Cloud Volumes ONTAP. Questo requisito garantisce che venga utilizzata una connessione Azure Private Link tra Cloud Volumes ONTAP e i relativi account di storage.
+
--
https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enabling-private-link.html["Scopri come Cloud Volumes ONTAP utilizza un Azure Private Link"^]

Porte:: Non c'è traffico in entrata verso l'agente della Console, a meno che non lo inizi tu o se viene utilizzato come proxy per inviare messaggi AutoSupport da Cloud Volumes ONTAP al supporto NetApp.
+
--
* HTTP (80) e HTTPS (443) forniscono l'accesso all'interfaccia utente locale, che utilizzerai raramente.
* SSH (22) è necessario solo se devi connetterti all'host per la risoluzione dei problemi.
* Le connessioni in entrata sulla porta 3128 sono necessarie se distribuisci sistemi Cloud Volumes ONTAP in una sottorete in cui non è disponibile una connessione Internet outbound.
+
Se i sistemi Cloud Volumes ONTAP non dispongono di una connessione Internet outbound per inviare i messaggi AutoSupport, la Console configura automaticamente tali sistemi per utilizzare un proxy server incluso con l'agente della Console. L'unico requisito è assicurarsi che il gruppo di sicurezza dell'agente della Console consenta le connessioni in entrata sulla porta 3128. Dovrai aprire questa porta dopo aver distribuito l'agente della Console.

proxy server:: NetApp supporta sia configurazioni proxy esplicite che trasparenti. Se usi un proxy trasparente, devi solo fornire il certificato del proxy server. Se usi un proxy esplicito, ti serviranno anche l'indirizzo IP e le credenziali.
+
--
* indirizzo IP
* Credenziali
* Certificato HTTPS

Indirizzo IP pubblico in Azure:: Se vuoi usare un indirizzo IP pubblico con la VM dell'agente della Console in Azure, l'indirizzo IP deve usare uno SKU Basic per assicurarti che la Console usi questo indirizzo IP pubblico.
+
--
image:screenshot-azure-sku.png["Uno screenshot della procedura di creazione di un nuovo indirizzo IP in Azure che ti permette di scegliere \"Basic\" nel campo SKU."]

Se invece usi un indirizzo IP SKU Standard, la Console usa l'indirizzo IP _privato_ dell'agente della Console, invece dell'IP pubblico. Se la macchina che stai usando per accedere alla Console non ha accesso a quell'indirizzo IP privato, le azioni dalla Console falliranno.

https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/public-ip-addresses#sku["Documentazione Azure: SKU IP pubblico"^]

--


Abilita NTP:: Se vuoi utilizzare NetApp Data Classification per analizzare le fonti di dati aziendali, dovresti abilitare un servizio Network Time Protocol (NTP) sia sull'agente della Console che sul sistema NetApp Data Classification, così che l'ora sia sincronizzata tra i sistemi. https://docs.netapp.com/us-en/data-services-data-classification/concept-cloud-compliance.html["Scopri di più su NetApp Data Classification"^]
